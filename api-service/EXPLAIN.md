# Как работает твой Go API Сервис (Гайд для новичков)

Этот документ объясняет архитектуру твоего приложения `api-service` и то, как проходит запрос от момента вызова до получения данных из базы.

## 1. Точка входа: Запуск
**Файл:** `cmd/api/main.go`

В Go всё начинается с функции `main()`. В этом файле происходит:
1. **Загрузка конфига**: Читаются переменные окружения (`internal/config`).
2. **Инициализация БД**: Устанавливается соединение с PostgreSQL и выполняется **AutoMigrate** (создание таблиц по моделям).
3. **Роутинг**: Настраивается библиотека `chi`, которая говорит серверу: "если пришел запрос на `/api/...`, передай его в `internal/handlers`".
4. **Запуск сервера**: Сервис начинает "слушать" порт 8080.

---

## 2. Маршрутизация (Routing)
**Файл:** `internal/handlers/routes.go`

Здесь определены все пути (эндпоинты). Когда запрос попадает в API, например `GET /api/users`, роутер смотрит в этот файл:
```go
r.Route("/users", func(r chi.Router) {
    h := NewBaseHandler[models.User]() // Мы создаем обработчик специально для модели User
    r.Get("/", h.List)                 // Этот метод вызовет список пользователей
})
```
Благодаря **Generics** (дженерикам), мы используем один и тот же код `NewBaseHandler` для всех сущностей (пользователи, лоты, мастера и т.д.).

---

## 3. Слой обработки запроса (Handler Layer)
**Файл:** `internal/handlers/base.go`

Это "мозг" обработки HTTP. Функция `List` делает следующее:
1. Достает параметры из URL (например, `?limit=20&offset=0`).
2. Обращается к **Repository**, чтобы получить данные.
3. Упаковывает результат в JSON: `{ "items": [...], "total": X }`.

---

## 4. Слой работы с БД (Repository Layer)
**Файл:** `internal/repository/repository.go`

Этот слой отвечает ТОЛЬКО за запросы к базе данных через ORM (GORM).
* Мы не пишем SQL вручную. Мы говорим GORM: `r.db.Find(&items)`.
* Это делает код безопасным от SQL-инъекций и очень чистым.

---

## 5. Модели данных (Models)
**Файл:** `internal/models/models.go`

Это "чертежи" твоих данных. Мы перенесли схему из Prisma в структуры Go.
* `json:"id"` — это **теги**. Они говорят Go, как превращать структуру в JSON.
* `gorm:"primaryKey"` — это инструкции для БД, как создавать таблицы.

---

## Жизненный путь одного запроса (`GET /api/users`):

1. **Клиент** делает запрос.
2. **main.go** (сервер) принимает его.
3. **routes.go** видит путь `/users` и направляет его в `BaseHandler[models.User].List`.
4. **base.go** (метод `List`) понимает, что нужно вернуть список. Он вызывает метод `GetAll` у репозитория.
5. **repository.go** (метод `GetAll`) делает запрос в PostgreSQL: `SELECT * FROM users LIMIT 20 OFFSET 0`.
6. **База данных** возвращает строки.
7. **Repository** превращает их в массив объектов `[]models.User` и отдает обратно в Handler.
8. **Handler** оборачивает массив в структуру `ListResponse` и отправляет клиенту JSON.

## Главные фишки Go в этом проекте:
* **Generics (`[T any]`)**: Позволяют написать один код для Repository и Handler, который работает с любой таблицей. Тебе не пришлось писать 23 почти одинаковых файла.
* **Struct Tags**: Позволяют легко связывать код с БД и JSON.
* **Graceful Shutdown**: В `main.go` есть код, который позволяет серверу закончить текущие запросы перед выключением, если ты нажал `Ctrl+C`.
