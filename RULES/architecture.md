- Проектирование: architecture -> state -> logic -> UI.
- Feature-based архитектура вместо file-based.
- Строгое разделение слоев: UI, State, Business Logic, API (SoC).
- Single Source of Truth.
- Централизованный и предсказуемый State.
- 1 файл/компонент/функция = 1 ответственность.
- Короткие функции, без глубокой вложенности.
- Side effects изолированы, API вызовы только в service layer.
- Минимизируй глобальное состояние, стремись к loose coupling.
- Модули должны быть легко удаляемы.
- Рефакторинг: сначала поведение, потом структура.
- Анализируй точки отказа до написания кода.
