- Проектируй код testable. Тестируй поведение, а не реализацию.
- Unit (логика), Integration (связи), E2E (сценарии).
- Тесты независимы (1 тест = 1 сценарий). Названия описывают поведение.
- Без дублирования setup. Минимизируй моки (только для внешних API).
- Не тестируй framework internals.
- Обязательно покрывай edge cases, failure scenarios, invalid inputs.
- Быстрые, стабильные (без flaky tests). Защита от regressions.
- Обновляй тесты вместе с логикой.
