- Проектируй схему под access patterns (модель -> запросы -> реализация).
- Data integrity важнее удобства записи (Single Source of Truth).
- Нормализуй для целостности, денормализуй для производительности.
- Используй constraints и unique ключи на уровне БД.
- Индексы только под реальные сценарии чтения, избегай избыточных.
- Без full scans и N+1. Выбирай только нужные поля (pagination).
- Транзакции для атомарности, locking для избежания race conditions.
- Безопасные повторные записи (idempotency), план обработки конфликтов.
- Миграции: пошаговые, обратимые, без деструктивных действий без плана.
- Soft delete только по бизнес-требованию (учитывай в запросах).
- Логирование (audit) критичных данных, без секретов.
- Наименьшие привилегии (least privilege), разделяй read/write.
- Защита от SQL injection (параметризованные запросы).
- Абстрагируй БД от бизнес-логики через Repository layer.
